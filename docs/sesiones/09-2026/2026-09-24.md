## Trabajo 2 — Login con Ibare, activable por `.env`

**Commit:** sin commit todavía

### Problema
Se pidió que Jichi pueda autenticar con Ibare —el servidor OAuth2 del GAD, corriendo en Docker— sin
tocar el código de Ibare, y que una variable de entorno elija entre Ibare y el login propio.

### Archivos modificados
| Archivo | Cambio |
|---|---|
| `config/jichi.php`, `.env.example` | Bloque `jichi.ibare`: `IBARE_ACTIVO`, `IBARE_URL`, `IBARE_CLIENT_ID`, `IBARE_CLIENT_SECRET` |
| `app/AuthIbare/` | Nuevo módulo: `AuthIbareServiceProvider`, `rutas.php`, `IbareController`, `IbareService`, `IbareException`, `VincularIbareCommand` |
| `bootstrap/providers.php` | Registra `AuthIbareServiceProvider` |
| `app/Http/Requests/Auth/LoginRequest.php` | Con Ibare encendido, el login por correo es solo para administradores |
| `app/Http/Controllers/Auth/AuthenticatedSessionController.php` | Manda la prop `ibare` a la pantalla |
| `resources/js/pages/auth/login.tsx` | Botón «Ingresar con Ibare»; formulario plegado como acceso de emergencia |
| `database/migrations/2026_09_01_100000_add_institutional_fields_to_users_table.php`, `app/Models/User.php` | Columna `mamore_id` (única) |
| `composer.json` | `firebase/php-jwt` para validar la firma |
| `docs/modulos/IBARE.md` | Nuevo, con el diagrama del recorrido |

### Solución
Authorization Code + PKCE. Jichi manda al navegador a Ibare, recibe un código, lo canjea servidor a
servidor por un JWT, valida firma, vencimiento, `aud = jichi` y `tipo_sujeto = funcionario`, y busca
el usuario por `users.mamore_id` (el `sub` del token). Después es la sesión normal de Laravel. Todo el código quedó en `app/AuthIbare/`, a pedido,
para que el módulo se lea y se desconecte de una sola pieza. Quien
no tiene usuario vinculado es rechazado, no creado. Jichi no necesita Docker: corre con
`composer run dev` en `127.0.0.1:8000` y llega a Ibare por `localhost:8001`.

Verificado sobre una SQLite descartable con un Ibare simulado que firma con RSA: entra el caso
válido y se rechazan sin cuenta, otro cliente, token de sistema, `state` falso y token vencido.
Contra el Ibare real: su JWKS se lee y la URL de autorización llega (responde `invalid_client`
porque falta registrar el cliente). Falta la prueba de punta a punta en el navegador.

prueba ahora deja la base limpia con solo el padrón de beneficiarios.

1. Pantalla de ingreso: nuevo botón «Ingresar con Ibare».
2. Ficha de usuarios: se agregó el número que vincula a cada usuario con su cuenta de funcionario.
3. Configuración: ajuste para encender o apagar el ingreso central.
4. Carga de datos de prueba: deja la base con solo los beneficiarios.

**Resultado:** El ingreso central quedó programado y probado por partes. Para usarlo falta
registrar Jichi en el servidor central y vincular a cada usuario con su cuenta de funcionario.
