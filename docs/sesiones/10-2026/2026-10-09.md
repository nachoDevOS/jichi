## Trabajo 1 — El despliegue en Coolify fallaba al bajar la fuente

**Commit:** (sin commitear)

### Problema
El redeploy en Coolify cortaba en `npm run build` con
`[plugin laravel:fonts] TypeError: fetch failed` → `getaddrinfo EAI_AGAIN fonts.bunny.net`.
El plugin de fuentes de `laravel-vite-plugin` descarga «Instrument Sans» de
fonts.bunny.net durante el build, y el contenedor de build no resolvió ese DNS.

### Archivos modificados
| Archivo | Cambio |
|---|---|
| `vite.config.ts` | `bunny('Instrument Sans')` → `fontsource('Instrument Sans')` |
| `package.json` / `package-lock.json` | se suma `@fontsource/instrument-sans` |

### Solución
La fuente ahora sale del paquete de npm, que `npm ci` ya instala en una etapa
anterior del build: el build de Vite no sale más a internet. Mismos pesos
(400–700) y misma familia, así que la pantalla no cambia. Verificado con
`npm run build` borrando antes la caché de fuentes del plugin
(`node_modules/.cache/laravel-vite-plugin`): genera los `instrument-sans-*.woff2`
sin red, y `tsc` en verde.

|---|---|
| `app/Http/Requests/Panel/CargarPagoRequest.php` | `comprobante` opcional: PDF/JPG/PNG/WEBP, tope `jichi.archivos.max_kb` |
| `app/Services/CargarPagoService.php` | sube con `StorageController::file()` a `pagos/`, manda la URL, borra si SIREB rechaza; ruta en `sireb_envio.comprobante` |
| `app/Sireb/SirebService.php` | `registrarPagoManual()` agrega `comprobante_url` al cuerpo (solo si hay) |
| `app/Http/Controllers/Panel/{Aprovechamiento,Carnet,Faena,Guia}Controller.php` | pasan `$request->file('comprobante')` |
| `resources/js/components/panel/pagos/tarjeta-recaudaciones.tsx` | el archivo entra al `useForm` con `forceFormData` |
| `docs/modulos/SIREB.md` | paso 2 de «Cargar el pago» |

### Solución
Se sube DESPUÉS de comprobar que la liquidación admite el pago —así no se suben
archivos que nunca se usan— y ANTES de llamar a SIREB. Va la URL completa, no la
ruta: SIREB no puede resolver una ruta de nuestro disco. **SIREB tiene que
aceptar el campo**: si lo ignora, no falla y el comprobante solo queda en Jichi.

## Trabajo 5 — Alta de funcionarios desde el panel, con su id de Ibare

**Commit:** (sin commitear)

### Problema
Entrando por Ibare salía «Su cuenta de funcionario (id 1002) no tiene acceso a
Jichi»: Ibare solo dice QUIÉN es (`mamore_id`); Jichi busca un usuario activo con
ese id y le da los permisos por su rol. No había pantalla para crearlo.

### Archivos modificados
| Archivo | Cambio |
|---|---|
| `app/Http/Requests/Panel/GuardarUsuarioRequest.php` | nuevo: nombre, `mamore_id` y rol; correo y clave solo sin Ibare o para el administrador (acceso de emergencia) |
| `app/Http/Controllers/Panel/UsuarioController.php` | `create()` / `store()`; el listado muestra «Ibare 1002» |
| `routes/panel.php` | `usuarios.create` / `usuarios.store`, permiso `usuarios.crear` |
| `resources/js/pages/panel/seguridad/usuarios-formulario.tsx` | nuevo formulario |
| `resources/js/pages/panel/seguridad/usuarios.tsx` | botón «Nuevo usuario» |
| `docs/modulos/IBARE.md` | límites conocidos |

### Solución
Sin clave, se guarda una al azar (la columna no admite null): entra solo por
Ibare. Usuario y rol se crean en una transacción.

Después, a pedido: el formulario quedó en nombre + id de Ibare + rol; correo y
clave solo para el administrador (acceso de emergencia), y el «correo» admite un
usuario sin @ (`sedag.encargado`). Para que eso sirva al entrar, `LoginRequest`
perdió la regla `email` y el campo del login dice «Correo o usuario»
(`auth/login.tsx`, `type="text"`).

Y edición (`usuarios.edit` / `usuarios.update`, permiso `usuarios.editar`), solo de
funcionarios: la cuenta de un beneficiario da 404 y se sigue manejando desde su
ficha. Mismo formulario; suma «Cuenta activa». La clave en blanco deja la que
tiene. Uno mismo no puede desactivarse ni quitarse el administrador.

Por último: con Ibare, entrar solo pide id de Ibare + rol + cuenta activa (Ibare
devuelve el `mamore_id`, nunca el correo). El bloque de correo y clave del
administrador quedó plegado detrás de «Darle acceso de emergencia»; destildarlo
borra el usuario de emergencia.
